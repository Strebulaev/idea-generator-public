# Разделение на публичный и приватный репозитории

## Решение

Проект разделяется на два репозитория:

- `idea-generator-private` — приватный. Содержит исходный код orchestrator, агентов, промпты `agents/*.yaml`, секреты Kilo/Qdrant. Без запускаемых workflow.
- `idea-generator-public` — публичный. Содержит poller и GitHub Actions workflow, который выполняется на бесплатных минутах публичного репо.

## Обоснование

- Публичный репо не должен содержать промпты и внутреннюю логику пайплайна.
- Публичный репо содержит только код для запуска задач, с минимальным раскрытием бизнес-логики.
- Разделение позволяет публиковать poller и workflow без раскрытия приватных данных.
- Разделение снижает риск утечки промптов и внутренней архитектуры.
- Публичный репо используется для экономии минут сборки GitHub Actions: в публичном репо минуты не ограничены, в приватном — ограничены.

## Границы ответственности

### Публичный репо

- Poller: читает задания из базы, запускает workflow в **публичном** репо, проверяет статус, пишет результат.
- GitHub Actions workflow, который выполняет пайплайн.
- README с описанием запуска.
- Без агентов, без промптов, без секретов LLM.

### Приватный репо

- Orchestrator и агенты.
- `agents/*.yaml` с промптами.
- Секреты: `KILO_GATEWAY_URL`, `KILO_API_KEY`, `IDEA_GENERATOR_MODEL`, `QDRANT_URL`, `QDRANT_API_KEY`.
- HITL issues создаются в этом репо.
- Без запускаемых workflow.

## Связь

- Публичный poller имеет доступ к приватному репо через GitHub App / PAT с правами на `issues:write` для создания HITL issues.
- Общая база данных: Qdrant, доступный из обоих репо.
- Публичный workflow может использовать код из приватного репо через checkout с PAT, или иметь минимальную копию orchestration logic.

## Исключения

- README публичного репо может упоминаять существование приватного репо, но без деталей внутренней логики.
- Issue tracker приватного репо используется для HITL.
